# RK3588 边缘部署说明（上位机 + NPU 推理）

> 本文档配套：`export_rknn.py`（PC/Linux 转换 ONNX→RKNN）、`board_infer.py`（板子 NPU 推理）。
> 目标：把上位机的"真实缺陷检测"从 PC-CPU 推理，迁移到 RK3588 的 NPU 上，实现边缘端毫秒级推理，并由 PyQt5 上位机做人机交互与结果展示。

---

## 0. 整体架构

```
┌─────────────────────┐        串口/以太网(JSON)        ┌──────────────────────────┐
│  PC 上位机 (PyQt5)  │  ◀──────────────────────────▶  │   RK3588 开发板          │
│  - 实时检测/历史/日志│   触发信号 / 图像 / 结果回传     │  - 相机取流             │
│  - NPU 监控(page_npu)│                                │  - NPU 跑 .rknn 推理     │
│  - 参数/通信设置     │                                │  - board_infer.py        │
└─────────────────────┘                                └──────────────────────────┘
         ▲                                                          ▲
         │ 模型权重                                                  │ 模型权重
   best.onnx / best_neu_*.pt ──export_rknn.py──▶ best_*.rknn  (INT8 量化)
```

形态选择（见正文末尾）：A=上位机留 PC 只部署模型（推荐）；B=整套 PyQt5 也上板。

## 1. 转换环境准备（一次性）

### 1.1 为什么不能在 Windows 本机跑
RKNN-Toolkit2 **只支持**：
- x86_64 Linux（Ubuntu 18.04 / 20.04 / 22.04）+ **Python 3.8 或 3.10**
- 或直接在 RK3588 板子（aarch64 Linux）上运行

当前开发机是 Windows + Python 3.13，无法安装/运行 RKNN-Toolkit2。因此转换步骤需在上面任一 Linux 环境执行。可选环境：
- **x86_64 Ubuntu 18.04/20.04/22.04**（物理机 / 虚拟机 VirtualBox·VMware / **WSL2** 均可）。注意：RKNN-Toolkit2 是**纯 CPU 库、不依赖 GPU 驱动**，所以 WSL2 提供的 x86_64 Linux 内核**能正常跑**（早期"WSL 不行"的说法已过时）；只是若追求与官方最一致的行为，用一台纯 Ubuntu 虚拟机或直接在板子上转最稳妥。
- **aarch64 RK3588 板子**（Debian/Ubuntu）也可直接在本机转。

### 1.2 在 Ubuntu 环境安装转换工具
```bash
# 建议用 miniconda 建一个干净 py3.10 环境
conda create -n rknn python=3.10 -y
conda activate rknn

# 安装 RKNN-Toolkit2（官方提供 .whl，见 https://github.com/airockchip/rknn-toolkit2/releases）
# 下载对应 python3.10 / x86_64 的包后本地安装：
pip install rknn_toolkit2-*-cp310-cp310-linux_x86_64.whl

# 转 .pt 时需要 ultralytics；纯转 .onnx 时不需要
pip install ultralytics opencv-python numpy
```

> 💡 **一键脚本**：本目录已提供 `setup_rknn_env.sh`，把整个「模型训练/」拷到 Ubuntu/WSL2 后 `bash setup_rknn_env.sh` 即可自动建 Python 3.10 环境、装 RKNN-Toolkit2、并一次性生成 `best.rknn` 与 `best_neu_yolo11n_aug.rknn`。手动步骤见下方 1.2~2.3。

### 1.3 把模型文件拷到该环境
把本项目的 `模型训练/` 目录（至少包含 `best.onnx` 或 `best_neu_yolo11n_aug.pt` 及 `datasets/`）复制到 Ubuntu 环境的某个目录，或从这里把文件传过去。

### 1.4 本机 Windows 一键生成（推荐：双击 `gen_rknn_pc.bat`）
本目录已提供 **`gen_rknn_pc.bat`**，在 Windows 上双击即可：自动检测 WSL2 → 把本目录拷进 Linux → 跑 `setup_rknn_env.sh` 生成 `.rknn` → 拷回本文件夹。前提是本机已有一个可用的 Linux 环境（二选一）：

| 路径 | 是否需要管理员 | 做法 |
|---|---|---|
| **WSL2 Ubuntu**（最轻量） | **仅需一次** | 以管理员身份运行 `wsl --install -d Ubuntu`，重启后设置用户名/密码 |
| **VMware Ubuntu 虚拟机**（已装） | **不需要** | 下载 Ubuntu 22.04 ISO → VMware 新建 VM → 安装时勾选 OpenSSH → `sudo apt install -y python3-venv python3-pip git` |

> 本项目实测：**当前 PC 不是管理员、WSL 未安装、VMware 已安装**。因此最省事的是用 **VMware 建 Ubuntu 虚拟机**（全程无需管理员）；若你能用管理员终端跑一次 `wsl --install`，则 WSL2 更轻量。

双击 `gen_rknn_pc.bat` 后：
- 若检测到 WSL2 → 自动完成拷贝/转换/拷回，本文件夹出现 `best.rknn`（合成 4 类）与 `best_neu_yolo11n_aug.rknn`（NEU 6 类，若转换成功）；
- 若未检测到 → 脚本会打印上面两种环境的安装指引并退出，装好后重跑即可。

> 只转 4 类（最快、不装 torch）可在 Linux 里手动：`bash setup_rknn_env.sh --four-only`。
> 转换依赖需联网（脚本自动从 GitHub/Gitee 拉 RKNN-Toolkit2 whl + PyPI 依赖；已内置清华镜像兜底）。

## 2. 执行转换（生成 .rknn）

### 2.1 合成 4 类模型（已有 best.onnx，直接转）
```bash
python export_rknn.py --src best.onnx --dst best.rknn \
    --calib ./datasets/neu_aug/images/val --imgsz 640 \
    --names scratch dent missing crack
```

### 2.2 NEU 6 类真实模型（从 .pt 转，脚本先导出 ONNX）
```bash
python export_rknn.py --src best_neu_yolo11n_aug.pt --dst best_neu_yolo11n_aug.rknn \
    --calib ./datasets/neu_aug/images/val --imgsz 640 \
    --names crazing inclusion patches pitted_surface rolled-in_scale scratches
```

### 2.3 量化参数说明
- `--calib` 指向验证/真实图目录（INT8 量化需要，目录越贴近真实分布越好；本项目 `datasets/neu_aug/images/val` 有 360 张，足够）。
- `mean_values=[0,0,0]` / `std_values=[255,255,255]`：对应 YOLO 输入的 /255 归一化。
- 默认量化 INT8，大幅加速并省显存；若精度掉太多可改 `quantized_dtype="fp16"`（脚本 config 处改）。

转换成功后得到 `best.rknn`（或 `best_neu_yolo11n_aug.rknn`），单个文件约几 MB，即可拷到板子。

## 4. 板子推理（board_infer.py）

把 `best_*.rknn` 和 `board_infer.py` 拷到板子，运行：

```bash
# 单张图
python3 board_infer.py --model best.rknn --source test.jpg --imgsz 640 \
    --names scratch dent missing crack

# 实时相机(USB/CSI)
python3 board_infer.py --model best.rknn --source 0 --imgsz 640 \
    --names scratch dent missing crack

# 推理结果通过串口发给上位机
python3 board_infer.py --model best.rknn --source 0 --imgsz 640 \
    --names scratch dent missing crack --serial /dev/ttyS0 --baud 115200
```

脚本输出每帧一行 JSON：
```json
{"frame":12,"ok":false,"defects":[{"cls":"dent","conf":0.93,"x1":120,"y1":80,"x2":210,"y2":175}],"infer_ms":8.2}
```
- `ok=false` → 存在缺陷（NG）；`ok=true` → OK（无缺陷）
- `infer_ms` 即 NPU 单帧推理耗时（RK3588 上 YOLOv11n 通常 8~15ms）

> 注意：`board_infer.py` 的后处理按 ultralytics YOLOv11 导出约定实现（输出 `[1,4+nc,8400]`，坐标在 640 letterbox 空间，类别需 sigmoid）。首次上板请用几张已知图对照 PC 端 ultralytics 结果校准，确认坐标/类别无误。

## 5. 上位机 ↔ 板子 通信（协议与对接点）

### 5.1 通信协议
板子→上位机，每行一条 JSON（UTF-8，`\n` 结尾）：
| 字段 | 含义 |
|---|---|
| `frame` | 帧序号 |
| `ok` | true=OK / false=NG |
| `defects` | 缺陷数组，含 `cls/conf/x1/y1/x2/y2` |
| `infer_ms` | NPU 推理耗时(ms) |

上位机→板子：发送触发指令（如 `"capture"` 或 Modbus 寄存器写），由板子取流推理后回传。

### 5.2 上位机对接位置（已实现 ✅）
- **`serial_bridge.py`**（新增）：`BoardSerialBridge(QThread)` 串口读取线程，按行解析板端 JSON，发 `result_received / connected / error` 信号。
- **`page_detect.py`**（新增"边缘模式"）：在"模型推理（真实）"组内加了 `边缘模式` 开关 + `🔌 连接 RK3588` 按钮 + `RK3588 未连接` 状态点。点连接后从 `config.json` 的 `serial.port/baud`（默认 COM3@115200）打开串口，收到 JSON 后在 `_on_edge_result` 里转成画布格式并**复用 `_apply_real_result`**（含 ROI 过滤、NG 闪烁、统计、入库）。停止检测会顺带断开串口。
- **`page_comm.py`**：串口参数（端口/波特率/数据位/停止位/校验/流控）已就绪，作为边缘模式的连接配置来源。板端 `board_infer.py` 的 `--serial /dev/ttyS0 --baud 115200` 与之对应。
- **`page_npu.py`**：NPU 监控仍是模拟数据；后续可改为读板子 `/sys/class/rknpu/rknpu0/...` 或板端 `psutil` 上报的真实利用率。

### 5.3 串口物理连接（PC ↔ RK3588）
1. PC 端插一个 **USB 转 TTL 模块**（CH340 / CP2102 / FT232，3.3V 电平）。
2. 接线（交叉）：
   | PC USB-TTL | ↔ | RK3588 UART（3.3V） |
   |---|---|---|
   | TX | → | RX |
   | RX | → | TX |
   | GND | ↔ | GND |
   | （不接 VCC，避免反向供电）|
3. **电平注意**：RK3588 GPIO 为 3.3V，**务必用 3.3V  tolerant 的模块，勿直接接 5V**。
4. RK3588 侧需在内核设备树里**使能对应 UART**（如 UART2），启动后会出现 `/dev/ttySx`；`board_infer.py` 用 `--serial /dev/ttySx` 指定（与 PC 侧 COM 号无关）。
5. PC 侧：设备管理器里看模块出现的 **COM 号**（如 COM3），在"通信设置"页把串口 `port` 设为它、`baud=115200`；上位机"实时检测→边缘模式→连接 RK3588"即可收结果。
6. 注意：RK3588 默认调试串口（FIQ/ttyFIQ0）常被 getty 占用，做数据通道请另选一个 UART，避免与控制台冲突。

### 5.4 网络连接：把 RK3588 与 PC 接入同一网络（TCP/IP 通道）
串口适合短距离点对点；**走以太网/TCP 更稳、带宽更高**，也是推荐方式。下面先让两者"在同一个网段"，再让板端把结果推给上位机。

#### 第一步：物理接入（任选其一）
| 方式 | 做法 | 适用 |
|---|---|---|
| **① 直连网线 + 静态 IP**（最省事） | 一根网线直连 PC 网口 ↔ RK3588 网口；**两端都设静态 IP、同一网段** | 无路由器、实验台 |
| **② 同一路由器/交换机** | PC 与 RK3588 都插到同一 LAN；可用 DHCP，或各自固定静态 IP | 工厂/实验室局域网 |
| **③ 同一 WiFi** | 若 RK3588 带 WiFi 模块，连到与 PC 相同的 WiFi AP | 无线部署 |

#### 第二步：分配静态 IP（推荐 ①/② 用固定地址，便于上位机配置）

> **网段怎么选**：方式①（网线直连）可以用任意私有网段，下面的 `192.168.1.x` 即可。
> 方式②③（走路由器 / 同一 WiFi）**必须跟着路由器实际网段走**，不能照抄 `192.168.1.x`。
> 查 PC 当前网段：PowerShell 执行 `Get-NetIPAddress -AddressFamily IPv4 | Select IPAddress, InterfaceAlias`
> （本机实测为 `192.168.1.100/24`，则该网段下板子应设为 `192.168.1.x` 的空闲地址，**板子实际部署在 `192.168.1.20`**。）

统一网段示例（直连场景）：
| 设备 | IP | 掩码 | 网关 |
|---|---|---|---|
| PC（Windows） | `192.168.1.100` | `255.255.255.0` | `192.168.1.1` |
| RK3588（Linux） | `192.168.1.20` | `255.255.255.0` | `192.168.1.1` |

**PC 侧（Windows，管理员 PowerShell）**：
```powershell
# 先确认网卡别名：Get-NetAdapter
New-NetIPAddress -InterfaceAlias "以太网" -IPAddress 192.168.1.100 -PrefixLength 24
Set-DnsClientServerAddress -InterfaceAlias "以太网" -ServerAddresses 192.168.1.1
```
（或：控制面板 → 网络连接 → 网卡 → IPv4 → 手动填写。）

**RK3588 侧（Debian/Ubuntu，NetworkManager）**：
```bash
sudo nmcli con mod eth0 ipv4.method manual \
  ipv4.addresses 192.168.1.20/24 ipv4.gateway 192.168.1.1
sudo nmcli con up eth0
# 无 NetworkManager 时改 /etc/network/interfaces：
#   iface eth0 inet static
#   address 192.168.1.20
#   netmask 255.255.255.0
```

#### 第三步：互 ping 验证
在 PC 上：
```powershell
ping 192.168.1.20
```
能通即"在同一网络"。（RK3588 默认可能禁 ping，需通时再排查防火墙 `ufw`。）

#### 第四步：启用板端 TCP 结果推送
板端 `board_infer.py` 新增 `--tcp-port`（如 `9000`）即可把每帧结果 JSON 推送给所有上位机客户端：
```bash
python3 board_infer.py --model best.rknn --source 0 --imgsz 640 \
    --names scratch dent missing crack --tcp-port 9000
```

#### 第五步：上位机接入（边缘模式 → 网络）
1. 打开上位机 → **实时检测** 页 → "模型推理（真实）"组的 **边缘部署 (RK3588)**。
2. **连接方式** 选 `网络 (TCP)`；**地址** 填 `192.168.1.20`；**端口/波特** 填 `9000`。
3. 点 `🔌 连接 RK3588` —— 状态点变绿即表示 TCP 通道建立，随后每帧结果自动渲染到画布（ROI 过滤/NG 闪烁/统计/入库全部复用）。
4. 选择逻辑在 `page_detect.py._toggle_edge`：根据下拉在 `BoardSerialBridge`（串口）与 `BoardTcpBridge`（TCP）间切换，二者信号接口一致。

> 上位机侧网络接收线程见 `tcp_bridge.py`（`BoardTcpBridge`，与 `serial_bridge.py` 同接口）。

### 5.5 上位机 NPU 监控页读取板端真实负载（已实现 ✅）

`page_npu.py` 的"数据来源"现在支持三种模式：
- **模拟数据**：本地随机值，无板子时调试 UI 用（兜底）。
- **板端串口**：经 `serial_bridge.BoardSerialBridge` 连板子串口，接收 `type:"stats"` 状态 JSON。
- **板端TCP**（推荐）：经 `tcp_bridge.BoardTcpBridge` 连板子 IP:端口，接收同一通道推送的状态 JSON。

板端 `board_infer.py` 已内置 `StatsReporter` 后台线程（默认 1s 一次），读取 RK3588 真实 NPU 三核负载（`/sys/kernel/debug/rknpu/load`）、芯片温度（`/sys/class/thermal/thermal_zone0/temp`）、内存（`/proc/meminfo`），并附上实时 `fps` 与单帧 `infer_ms`，以 `{"type":"stats",...}` 经**与检测结果相同的串口/TCP 通道**推送。上位机桥接线程按 `type` 字段分流：检测结果 → `result_received`；状态 → `stats_received` → 喂给 NPU 监控页渲染（三核负载条 / 温度 / 内存 / 平均·峰值负载 / 帧率 / 单帧耗时）。

> 注意：串口为点对点，NPU 页"板端串口"与"实时检测→边缘模式→串口"**不能同时使用同一 COM 口**；推荐用 TCP（TcpResultServer 支持多客户端，NPU 页与检测页可同时连）。

### 5.6 无板子时的协议级替身：`板端模拟器.py`（已实现 ✅）

**为什么需要它**：NPU 监控页自带的"模拟数据"是在 **UI 内部直接造数**的，桥接线程、JSON 解析、stats/result 分流全被绕过——能看界面，但**验证不了链路**。等真板子接上时，出问题很难分清是链路 bug 还是硬件问题。

`板端模拟器.py`（位于项目根目录）把**板子这一端**用软件顶替：

| 对比 | 上位机内部「模拟数据」 | 板端模拟器（本方案） |
|---|---|---|
| 数据在哪产生 | UI 里直接造 | 独立进程，经 **真实 TCP socket** 发出 |
| 桥接线程 | 被绕过 | ✅ 真实走 `BoardTcpBridge` |
| JSON 解析/分流 | 被绕过 | ✅ 真实逐行解析 + `type` 分流 |
| 协议一致性 | 无保证 | ✅ 与 `board_infer.py` **逐字段一致** |
| 换真板子 | 需改代码 | ✅ **只换 IP，上位机零改动** |

**启动**（双击 `启动板端模拟器.bat`，或命令行）：

```bash
python 板端模拟器.py --port 9000 --fps 10 --ng-rate 0.35
#   --port    监听端口（默认 9000）
#   --fps     推理帧率（默认 10）
#   --ng-rate 出缺陷帧的比例（默认 0.35）
```

启动后它会打印本机所有可用 IP，例如：

```
在上位机里填这些地址之一：
   · 本机回环   127.0.0.1:9000   （同一台电脑测试用）
   · 局域网     192.168.1.100:9000
```

然后上位机：
- **NPU 监控页** → 数据来源「板端TCP」→ 地址填上面任一 IP → 端口 `9000` → 连接
- **实时检测页** → 边缘模式「网络(TCP)」→ 同上 → 启动

**行为仿真**：三核错峰（`core0` 最忙、`core2` 最闲）、约 18% 概率触发持续 4~8 步的**推理脉冲**（三核冲到 85~97%，帧耗时 7.5~12ms）、温度随平均负载按热惯性爬升（38~88℃ 夹紧）、内存随推理小幅上涨后缓慢回收、`fps` 由真实帧计数算出。缺陷类别用 NEU-DET 真实六类（`crazing/inclusion/patches/pitted_surface/rolled-in_scale/scratches`），置信度集中在 0.55~0.97。

> 已纳入回归测试 **T23**：起模拟器 → 用真实 `BoardTcpBridge` 连接 → 校验 stats/result 分流、字段完整性、缺陷结构、负载动态性。

### 5.7 板端一键部署：`setup_board.sh`（已实现 ✅）

拿到真板子后，把整个「模型训练/」目录拷到板子（U 盘 / `scp` / `rsync`），执行：

```bash
cd 模型训练
chmod +x setup_board.sh
./setup_board.sh                       # 默认：自动找 .rknn、TCP 9000、摄像头 0、开机自启

# 常用变体

./setup_board.sh --source /home/pi/images        # 用图片目录代替摄像头
```

脚本会依次完成 6 步：① 检查架构与 RKNPU 设备节点 ② 自动定位 `.rknn`（找不到会提示先跑 `setup_rknn_env.sh`）③ 建 venv ④ 装 `rknn-toolkit-lite2`（优先用目录内本地 whl，离线也能装）+ opencv/numpy/pyserial ⑤ 生成 `start_board.sh` ⑥ 注册 systemd 服务 `defect-board` 开机自启。

服务手动控制：

```bash
sudo systemctl start   defect-board
sudo systemctl stop    defect-board
sudo systemctl status  defect-board
journalctl -u defect-board -f          # 实时日志
```

### 5.8 板端总入口：`deploy_board.sh`（推荐，一条命令走完全程 ✅）

`setup_board.sh` 只负责「装运行时 + 起服务」，但它**默认要你先把 `.rknn` 转好**，否则第 2 步就退出。而 `.rknn` 本来就能在板子上转（`export_rknn.py` 支持 aarch64），所以新增一个**总入口**把「转模型 + 装运行时 + 起服务 + 自启」全串起来：

```bash
# 在 PC 上把整个目录传到板子（板子实测在线：root@<板子IP>，Ubuntu 22.04）
scp -r 模型训练 root@<板子IP>:/root/
# 登录板子并执行
ssh root@<板子IP>
cd /root/模型训练
chmod +x deploy_board.sh
./deploy_board.sh                # 一条命令搞定全部
```

它做的事（6 步）：
1. **检查环境**：架构 aarch64、`/sys/class/rknpu` 设备节点、设备树型号；
2. **建隔离 venv + 装 opencv/numpy**：用**完全隔离**的 venv（不挂系统 site-packages），`pip install opencv-python-headless`，避免系统 numpy/opencv/protobuf 版本与 rknn 依赖（`numpy<=1.26.4`、`protobuf==3.20.3` 等）冲突；
3. **装 RKNN 运行时**：
   - `rknn-toolkit-lite2`（NPU 推理，必需）：从 `rknn-toolkit-lite2/packages/` 装；
   - `rknn-toolkit2`（转模型用）：从 `rknn-toolkit2/packages/arm64/` 装；
   - 下载策略：**本地 whl 优先 → 官方 `raw.githubusercontent.com` → Gitee 镜像 → `git` 浅克隆（仅取对应 packages 目录）兜底**；whl 按板子实际 Python 版本（`cp310`/`cp311`/…）自动选；
4. **转模型**：用现成的 `best.onnx` → `best.rknn`（合成 4 类）。**注意**：rknn-toolkit2 在 aarch64 上依赖 `torch`（约 200MB），脚本会自动装齐 `torch`/`onnx`/`onnxruntime` 等，板上转换属 **best-effort**；
5. **生成 `start_board.sh`**（自动带上类别名 `--names`）；
6. **注册 systemd 自启** + 打印上位机对接信息（板子 IP 自动探测）。

常用变体：

```bash
./deploy_board.sh --source /home/pi/images   # 用图片目录代替摄像头
./deploy_board.sh --serial /dev/ttyS0        # 同时经串口推送
./deploy_board.sh --skip-convert             # .rknn 已存在，跳过转换（仅装运行时+起服务）
./deploy_board.sh --six-class                # 额外转 NEU 6 类模型（需 ultralytics，torch 已装则很快）
./deploy_board.sh --no-autostart             # 不注册开机自启
```

> ⚠️ **板上转换若失败**：aarch64 转模型官方不保证（rknn-toolkit2 依赖 torch 较重）。若 `./deploy_board.sh` 提示 rknn-toolkit2 / torch 装不上，改用 **PC 的 WSL/Ubuntu** 跑 `setup_rknn_env.sh` 生成 `best.rknn`，再 `scp best.rknn root@<板子IP>:/root/模型训练/`，然后 `./deploy_board.sh --skip-convert`。
> NEU 6 类模型 `best_neu_yolo11n_aug.pt` 需 ultralytics 才能导出 ONNX；板子已装 torch 时加 `--six-class` 即可，否则建议在 x86 Ubuntu 用 `setup_rknn_env.sh` 转好再拷过来。
