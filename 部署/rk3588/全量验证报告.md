- conf=0.25 时 crazing 漏检 2 张（`crazing_016`、`crazing_027`），降阈值至 0.20 后全部召回，且未引入其它类误检。

## 三、与 PC 端 onnxruntime 基线的一致性

本次部署修复了 `rknn.config(std_values=255)` 导致的「输入双重归一化」问题后，板端
NPU 输出与 onnxruntime 高度一致（同一张 crazing 测试图）：

| 输出 | onnxruntime | RK3588 NPU | 误差 |
|---|---|---|---|
| box 最大值 | 639.501 | 640.000 | 0.08% |
| crazing 置信度 | 0.4021 | 0.4031 | 0.25% |

说明 FP16 量化在 NPU 上的精度损失可忽略，模型在边缘端的推理结果可信。

## 四、部署链路

1. **转换**：`模型训练/export_rknn.py`（ONNX → FP16 RKNN），关键配置：
   - `mean_values=[[0,0,0]]` + `std_values=[[255,255,255]]`，**host 端送 uint8 [0,255] NHWC**
   - 切勿在 host 端再 `/255`，否则输入被压缩 255 倍（分类头压塌、box 看似正常的隐蔽 bug）
2. **推理**：`board_server.py`（TCP 9000，~8 FPS 含 JPEG 编码/推流）或 `board_infer.py`（纯推理）
3. **上位机**：`page_detect.py` 边缘模式接收板端 JSON 结果，统计/入库/画框

## 五、附：验证方法（可复现）

```bash
# 板端（RK3588）
cd /root/rknn_convert
python3 batch_verify.py /root/rknn/best_neu6.rknn /root/rknn/testset 0.20 --json result.json
```

测试集位于板端 `/root/rknn/testset/`（180 张，文件名 `类别_序号.jpg`），脚本按文件名
前缀自动比对真实类别，输出每类检出率 / 平均置信度 / 漏检明细。
