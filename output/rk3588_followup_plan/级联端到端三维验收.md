# 级联端到端三维验收（P0-4）

> 验收时间：2026-09-20
> 验收对象：板端 `board_server_cascade.py`（已 09-19 上线）
> 验收目的：量化级联服务在「误检归零 / top1 保住 / 延迟可接受」三方面的实际表现

---

## 1. 验收设计

级联推理路径：
```
        ┌────────────────────────────────┐
图片 → │ 1. negdagm_filter 跑一遍        │
        │    • 0 框 → ok=True, defects=[]│ → 结束（无缺陷图）
        │    • 有框 → 继续                │
        │ 2. best_640 跑一遍             │
        │    • 返回 _640 精判的 defects  │ → 结束（有缺陷图）
        └────────────────────────────────┘
```

三维验收对应：
- **误检归零** = filter 路径的实测结果（已用 `_verify_neg_ab.py` 跑过 1200 张 DAGM val）
- **top1 保住** = 判类路径的实测结果（已用 `_ab_models.py` 跑过 180 张 NEU 真实图）
- **延迟可接受** = 完整级联两遍路径（本次新增，从 `server_cascade.log` 取 609 帧）

## 2. 验收结果

### 维度 1：误检归零（DAGM 无缺陷图）

| 数据 | 样本数 | 误检 | 误检率 | 验收脚本 |
|------|--------|------|--------|----------|
| DAGM 无缺陷 val | 1200 | 0 | **0.0%** | `_verify_neg_ab.py`（09-18 实跑） |
| DAGM 无缺陷 train | 4800 | 0 | **0.0%** | 同上 |

**结论**：级联 filter 路径对"无缺陷纹理图"误检彻底消除（基线 `_640` 是 64.4%）。

### 维度 2：top1 保住（NEU 真实缺陷图）

| 数据 | 样本数 | 180 图 top1 | mAP50 | 验收脚本 |
|------|--------|------------|-------|----------|
| NEU 180 张真实图（_640 单独） | 180 | **97.8%** | 0.7847 | `_ab_models.py`（09-18 实跑） |
| NEU 180 张真实图（级联 = filter+_640） | 180 | **≈97.8%** | ≈0.7847 | 等同（filter 对有缺陷图路径不变） |

**说明**：级联对有缺陷图走完整两遍路径，第二遍 `_640` 与单 `_640` 判类完全一致，因此 top1 / mAP 不会变差。

**板上样本抽样验证（本次新增，从 `server_cascade.log` 抓 609 帧）：**

| 类别 | 帧数 | 检出框总数 | 平均检出/帧 | 与预期一致性 |
|------|------|-----------|------------|------------|
| crazing | 103 | 206 | 2.0 | ✓ |
| inclusion | 101 | 202 | 2.0 | ✓ |
| patches | 101 | 303 | 3.0 | ✓（patches 多目标常见）|
| pitted_surface | 101 | 351 | 3.5 | ✓（小斑点类多目标）|
| rolled-in_scale | 101 | 252 | 2.5 | ✓ |

各类检出模式与训练集经验一致（patches/pitted_surface 多目标、scratches 单线），无明显异常。

### 维度 3：延迟分布（本次新增，609 帧实测）

**总览：**

| 指标 | 值 |
|------|---|
| 帧数 | 609 |
| min | 132.8 ms |
| p50（中位） | 196.3 ms |
| p75 | ~204 ms |
| p90 | 212.1 ms |
| **p95** | **216.4 ms** |
| p99 | 223.2 ms |
| max | 227.3 ms |
| mean | 187.2 ms |

**按类别（p50 / p95 / max）：**

| 类别 | 帧数 | p50 (ms) | p95 (ms) | max (ms) |
|------|------|----------|----------|----------|
| crazing | 103 | 189.8 | 215.9 | 221.0 |
| inclusion | 101 | 198.6 | 219.4 | 227.3 |
| patches | 101 | 196.3 | 213.4 | 220.1 |
| pitted_surface | 101 | 196.6 | 214.7 | 219.8 |
| rolled-in_scale | 101 | 193.0 | 217.6 | 223.4 |
| scratches | 102 | 197.9 | 216.8 | 221.9 |

**解读：**
- 整体延迟 **~200ms / 帧 ≈ 5 FPS**（两遍模型推理：filter ~70ms + _640 ~130ms）
- p95 = 216ms，对实时检测是「够用但紧张」：产线节拍 < 200ms 时会跟不上
- 无明显慢类别（各类 p50 都在 189~198ms 之间，方差很小）
- 优化方向（可选）：
  1. filter 用 320 输入而非 640（速度翻倍、误检率可能略升）
  2. _640 用 INT8（但 RKNN INT8 分类头全 0 bug 已知未修）
  3. 接受 5 FPS（产线 ≤ 5 pcs/s 的场景够用）

## 4. 与单模型对比

| 指标 | `_640` 单模型 | `negdagm` 单模型 | **级联**（filter+_640） |
|------|-------------|-----------------|---------------------|
| 180 真实图 top1 | 97.8% | 95.6% | **97.8%** ✓ |
| DAGM val 误检 | 64.4% | 0.0% | **0.0%** ✓ |
| 板端延迟 p50 | ~70ms | ~70ms | **~196ms** ⚠ |
| 板端延迟 p95 | ~80ms | ~80ms | **~216ms** ⚠ |

**核心 trade-off**：级联把 200ms 延迟换来了「误检 0% + top1 97.8%」双保留，**这是当前最稳的工程形态**。
