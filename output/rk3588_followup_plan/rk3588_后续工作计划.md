# RK3588 项目后续工作计划

> 编制时间：2026-09-20
> 依据：《实验改进分析与后续计划》（2026-09-08，对标项目：Orin Nano 39 类金属表面缺陷检测）的方法论与节奏，结合 rk3588 项目当前实际进展（6 类 NEU 钢材缺陷、双模型级联已上板、上位机 PyQt5 6 页全链路）定制。
>
> 核心原则：**借鉴 Nano 那份计划的"方法论骨架"（评估口径 / 弱类攻坚 / 数据治理 / 工程闭环），按 rk3588 的"现实基础"重排优先级**。两个项目基础不同——Nano 是 39 类 mAP0.795 的优化期、rk3588 是 6 类 mAP0.783 的工程完成期。

---

## 0. 两个项目基础对照（先校准尺度，再谈借鉴）

| 维度 | Orin Nano 项目 | rk3588 项目 | 借鉴启示 |
|------|---------------|------------|---------|
| 类别 | 39 类（多源融合） | 6 类（NEU 钢材） | rk3588 弱类只有 6 个，优化空间小但更容易做精 |
| mAP50 | 0.795（公开数据上限） | 0.783（_640 基线） | rk3588 仍可向 0.80 推 |
| 底座 | YOLOv11m | YOLOv11n | nano 体积已压到底，量化/蒸馏收益小 |
| 部署 | TensorRT FP16 GPU | RKNN FP16 NPU | rk3588 改 INT8 受限（板端归一化 bug 已知） |
| 已有底座数据 | 25,689 图 / DAGM 2000 负样本 | 1,440 NEU + 6,000 DAGM 负样本 | rk3588 负样本闭环已建立，但 NEU 域内数据偏少 |
| 上板 | 单模型 | **双模型级联**（09-19 上线） | rk3588 工程量更靠后（架构/协议已就位），改进聚焦优化 |
| 上位机 | Nano GUI | PyQt5 6 页（统计/相机/检测/通信/...） | rk3588 已有数据入口，难例回流机制现成 |

**总体判断**：rk3588 项目**已跨过"工程完成期门槛"**（上位机+板端全链路打通、双模型级联已上板），下一阶段的胜负手和 Nano 一致——**评估口径的可信度 + 弱类 + 数据闭环**——但**优先级和实现路径不同**（详见下文）。

## 一、问题清单（按 rk3588 实际定优先级）

### P0 评估口径与对照基准 —— 必须先做（影响一切结论）

1. **calibration / holdout 双集合分离**。当前所有"提升"（aug / neg / 1:1 / 1:2）的验收都跑在同一个 NEU val 上，阈值与评估同源，存在"评估集过拟合"风险。**改进**：把 NEU val 360 切成 180 calibration + 180 holdout，所有后续阈值/超参在 calibration 上选、在 holdout 上汇报。
2. **per-class 阈值表是否真有效**。当前 `board_server.py` 用了 inclusion 0.16 / scratches 0.30 的 per-class 阈值，但 180 图 top1 实测是**和全局 0.20 完全一致**（97.8%/100% 覆盖）。**改进**：在 calibration 集上系统扫一遍 per-class 阈值表，看是否真的"零训练成本召回收益"；若无效可统一回 0.20 让模型行为更可预测。
3. **多模型 A/B 报告统一口径**。`_640 / aug2 / negdagm(1:1) / negdagm(1:2)` 四个模型各跑过验证但口径散落在不同日志。**改进**：一次性出统一对比表（mAP50 / mAP50-95 / 180图 top1 / 6 类逐类 / DAGM 误检 / 混淆对），用于论文和后续决策。
4. **级联效果量化报告**。双模型级联（negdagm 过滤 + _640 判类）是 09-19 上线，但还没有量化的"端到端"验收（误检归零 + top1 不掉 + 延迟分布）。**改进**：跑一次完整的级联三维验收，写成单独报告。

### P1 模型能力短板 —— 仍是改进主战场

5. **scratches↔inclusion 跨类混淆**。A/B 实测：scratches 被判 inclusion 的有 4 张（PC 与板端同错，模型跨类混淆，非部署问题）。top-2 双候选只能救 2/4 张。**改进（按性价比）**：
   - **scratches/inclusion 混淆专项数据集**：从 NEU 训练集各取 100 张，让模型做"二选一"微调（lr 极低 1e-5 跑 30 轮），专门压这两类的区分边界；
   - **合并为 1 类**（如果业务允许）—— 1 个"暗色条纹"大类的混淆消失；
   - **per-class 阈值**在 scratches 侧的微调（但 P0 步骤先证明有效再调）。
6. **crazing 召回偏低**。180 图 top1 30/32，但级联后 crazy 检出数从 30 降到 28（_640 自有漏检 + 级联 0 框路径吃掉了 1 张）。**改进**：crazing 单类补样（合成或爬同源数据集） + 单独降阈（先 P0 验证有效）。
7. **DAGM 域外泛化已用负样本压住，但换域还可能崩**。当前 0% 误检是在 DAGM 域内，真实产线钢带纹理会怎样未知。**改进**：上板后跑一周的现场实拍日志，用上位机的存图 + 入库做"真实域误检监控"，纳入 P2 数据治理。
8. **6 类混洗 vs 持续补样**。NEU 单数据集 1440 训练图已经做过 1:1 增强（aug2 5760 图 + DAGM 负样本 4800），但 scratches/inclusion 仍难分。**改进**：先 P5 专项，**再**考虑换数据源（Severstal / GC10 钢材类做域内补样，但要先做语义映射审计——见 P2-11）。

### P2 数据治理 —— 长期可靠性

9. **数据完整性体检**。已有 1 次事故（cv2.imwrite 中文路径静默失败导致 4320 张增强图丢失→aug2 其实是假增强集）。**改进**：把 `_dataset_check.py`（数量、孤儿、图签一一对应、框合法性）固化为 `train_*.py` 的前置必跑，不通过就拒绝训练。
10. **NEU 单域 → 域内补样**。负样本已用 DAGM 解决"域外无缺陷"问题，但"域内细微缺陷"（边界样本、标注噪声）还没专项。**改进**：人工复核 NEU 训练集 200~300 张，对照 scratches/inclusion 边界样本做标签审计，输出 `neu_label_audit.md`。
11. **类映射审计**（如新增域外数据源）。**改进**：新增任何数据集前都先做 `class_mapping_audit.md`（源类 → 目标类 + 理由 + 抽样人工复核），避免 GC10 那种"语义重叠"标签噪声。
12. **混淆矩阵 + Top-10 混淆对清单**。180 图已经能看到 4 张 scratches→inclusion，但缺少**全套验证集的混淆矩阵**。**改进**：在 holdout 集上跑一次完整混淆矩阵 + Top-10 混淆对清单，纳入每周基准回归。

### P3 部署工程与业务闭环

13. **延迟分布量化**。级联上线后只有抽样的几帧耗时（70~215ms），没有统计。**改进**：上位机跑 30 分钟连续检测，统计 p50/p95/p99 延迟，看是否需要把级联第一遍也精简（如用更小输入先过滤）。
14. **双模型级联 → 掉电自启修复**（小项，但实际已踩过）。当前 S99board 自启的是旧单模型服务，板子掉电后**级联会失效、需手动切换**。**改进**：把 `start_cascade.sh` 接入 S99board，或改 `start_srv.sh` 默认跑级联版，**确保级联成为默认服务**。
15. **per-class 阈值简化候选**。级联上线后，"inclusion 降阈救 scratches"那套逻辑**理论上不再需要**（_640 是判类主力，已经能区分 scratches）。**改进**：在 calibration 上 A/B：①保持 per-class ②统一 0.20，top1 / 误检无显著差异就统一回 0.20，简化代码和论文叙述。
16. **难例回流机制**。上位机已有"NG 存图 + 入库"（page_detect.py 缺陷统计 + `存证_*`目录），但没制度化成"复核→入库→周度训练"。**改进**：写 `回流周报脚本 _weekly_feedback.py`，从 `存证_*` 目录 + SQLite NG 记录里挑"低置信/边界 NG"做候选难例，人工勾选后入 `_hardpool/` 等待下轮训练。
17. **可复现性归档**。`_640 / negdagm(1:1) / negdagm(1:2) / 级联` 四个版本权重 + 各自的训练 yaml + 数据集 md5 + 随机种子。**改进**：写 `experiments/runs_log.md` 记录每次实验（目的 / 配置 / 结果 / 结论 / 权重路径），论文/答辩时直接用。

### P4 论文 / 答辩物料（持续产出，单独列）

18. **论文初稿**已基于"RK3588 轻量化工业缺陷检测系统"出第一版（`论文初稿/基于RK3588...（初稿）.docx`），**待补**：
   - 负样本消融实验（误检 64.4%→0% vs top1 97.8%→95.6% 的权衡，方案 A 失败原因）
   - 双模型级联工程方案（动机 / 设计 / 延迟 / 效果）
   - 实际指标表（_640 / negdagm / 级联 三列）
19. **图件**：confusion matrix 图、级联架构图、per-class 阈值曲线图（用 `make_figs.py` 同套）。
20. **答辩问题预案**：自启/回滚/INT8/级联延迟等已问过的问题备好答案（已在工作日志里），新风险点（级联掉电自启、双 NPU 显存竞争）补充进预案。

## 二、四周计划与安排（按 rk3588 现实重排）

| 周次 | 主题 | 关键任务 | 交付物 | 验收标准 |
|------|------|----------|--------|---------|
| **第 1 周（09-20 起）** | 口径冻结 + 级联量化 | ① NEU val 切 calibration/holdout；② 统一评估脚本（固定 conf/IoU/标注规范）；③ per-class 阈值 A/B（保留 vs 统一 0.20）；④ 级联端到端三维验收（DAGM 误检 + NEU top1 + 延迟分布）；⑤ 统一多模型对比表 | 基准测试集 v1、统一评估报告、级联验收报告、四模型对比表、confusion matrix | 0.783 在 holdout 上复现偏差 ≤0.01；级联三维有数字；per-class 阈值必要性有结论 |
| **第 2 周** | 弱类攻坚 + 数据治理 | ① scratches/inclusion 混淆专项数据集 + 微调（lr=1e-5, 30 轮）；② 数据体检脚本固化为训练前置；③ 现场实拍一周（上位机跑连续检测），建立真实域误检监控基线；④ 难例回流周报脚本上线 | 混淆专项微调 v1、数据体检脚本、真实域监控基线、回流周报 v1 | 4 张 scratches 误判 ≥3 张救回；数据体检纳入 train 必跑；真实域误检率有数 |
| **第 3 周** | 域内补样 + 工程收尾 | ① NEU 200~300 张标签审计（neu_label_audit.md）；② 若 scratches/inclusion 微调不够，再试"合并为 1 类"或换数据源（先做类映射审计）；③ 板端自启切级联版（S99board 改 start_cascade.sh）；④ 实验台账 v1（experiments/runs_log.md） | 标签审计报告、类映射审计表（若用新源）、自启切级联、实验台账 | 弱类指标不掉；掉电重启自动级联；台账覆盖所有历史实验 |
| **第 4 周** | 论文完善 + 答辩准备 | ① 论文补「负样本消融 + 双模型级联」两节；② 补图（confusion matrix / 级联架构 / 阈值曲线）；③ 答辩问答预案 v2（覆盖掉电自启、级联延迟、INT8、混淆根治等）；④ 最终上板权重确认（级联 + 微调版，若有） | 论文 v2、图件 v2、答辩预案 v2、上板权重冻结 | 论文结构完整；答辩预案能自洽；上板版本确定不再迭代 |

**持续机制**：
- 每周五跑一次 calibration/holdout 双集回归，指标异动当天定位；
- 上位机连续检测时实时监控 NPU 延迟分布；
- 难例周报每周日自动出，下周一汇总到训练候选。

## 三、风险与依赖

| 风险 | 影响 | 应对 |
|------|------|------|
| scratches/inclusion 混淆微调后负样本抑制力回退 | top1 救不回，误检升 | 微调只改 backbone 末层 + lr 极低 + 保留 negdagm 过滤路径（级联架构能隔离） |
| 现场实拍一周暴露级联延迟不够 | 板端 7FPS 不可用 | 上位机已存 24 张样本可先看；延迟超 200ms 考虑把 negdagm 换更小输入（如 320）先做粗筛 |
| 板子掉电自启切级联 → 旧 board_server 残留 | 上位机连上"假"服务 | 改 S99board 之前先做：① 现有 start_srv.sh 加 cascade 默认；② 验证一遍后下板子实测掉电恢复 |
| DAGM 域外负样本与 NEU 域差过大 | 后续换真实产线负样本时，老模型可能不收敛 | 边采真实图边做最小子集实验（先 500 张试），而不是一上来就混 6000 张 |
| 论文/答辩时间逼近 | 优化窗口不够 | 第 1 周必完成 P0 全部；第 2-3 周弱类攻坚与论文同步推进；第 4 周只允许"补文字/补图" |

## 五、与 Nano 项目对标的"可学 / 不可学"

| Nano 那份计划的做法 | rk3588 是否照做 | 理由 |
|--------------------|----------------|------|
| 切 calibration/holdout 双验证集 | **照做** | 通用方法论，对评估可信度立竿见影 |
| per-class 阈值表 | **做，但先验证必要性** | 180 图 A/B 已显示 per-class 对当前模型"零效果"——先验证，再决定保留/简化 |
| 现场实拍 200~500 张 | **做（但换形式）** | 上位机已有连续检测能力，"实拍"等价于"上位机存图 + 入库一周" |
| DAGM 2000 张 OK 负样本 | **已做（6000 张）** | 反而比 Nano 量大；问题是域差，可学 Nano 的"双库分别回归"做法 |
| 弱类召回 0.310 → 0.40 | **做（但目标不同）** | rk3588 弱类是 scratches/inclusion 跨类混淆，不是单纯召回——专项微调更对路 |
| MVIT 10 类补样 ≥300 框 | **暂不做** | rk3588 只有 6 类，NEU 1440 已够；先做标签审计再决定 |
| INT8 量化 | **暂不做** | 已知 rk3588 RKNN INT8 分类头全 0 疑似归一化 bug（记忆），不是优先级 |
| ROI 5MP→256 裁切 | **暂不做** | NEU 原图 200×200 已小于 ROI 裁切；不适用 |
| 39 类混淆矩阵 + Top-10 混淆对 | **做（6 类版）** | 通用方法论；6 类矩阵更简单易做 |
| TensorRT 校准 | 不适用 | rk3588 走 RKNN 路径，量化为 FP16 固定 |
| 误报率/漏报率双口径业务指标 | **做** | 通用方法论，上位机已有 NG 存图/入库可支持 |
| 周五基准回归 | **做** | 通用方法论 |
| 实验台账 | **做** | 通用方法论 |

**核心借鉴结论**：Nano 那份计划的"骨架"（评估口径 / 弱类 / 数据 / 闭环）全可用；"细节"（39 类 / 5MP / INT8 / ROI）多不适用或已做。**第 1 周的 P0 全部任务是必做项**，直接决定后续所有结论的可信度。

---

> 总结：rk3588 项目**工程已闭环、改进窗口正打开**。下一阶段不再是"打通链路"，而是"把链路跑得更可信、更精细、更可持续"。这份计划是接下来四周的工作清单，按周推进，每周末回顾是否达成验收标准。
