# 评估口径核查报告：负 FP / P > 1 现象

**日期**：2026-10-21
**触发**：汇报材料里出现 `punching F1 = 1.077`、`water_slag_mark fp = -2` 两个"不可能"的数字，需要查清是 bug 还是口径。

---

## 一、核查结论（先说结果）

| 疑点 | 结论 |
|---|---|
| `punching F1 = 1.077` | **不存在**。实际 `F1 = 1.0000`（gt=74, tp=74, fp=0, fn=0），74 个框全对。此前是记录错误（与 `striated_scale` 的历史案例混淆） |
| `water_slag_mark fp = -2` | **不是 bug**，是默认口径的**已知内部不一致**。可通过 `--strict` 消除 |

---

## 二、根因：默认口径的内部不一致

`_calib_thres39.py` 默认采用与历史基线 `_eval_steel39.json` 完全对齐的口径：

- **匹配与类别无关**（class-agnostic，只看 IoU ≥ 0.5）
- **TP 记在真值类上**
- FP 则由 `fp = 该类预测数 − 该类 TP` 反推

这三条组合起来，当**模型把 A 类缺陷框成 B 类**时：

1. 该框因 IoU 足够，被匹配成功 → 计入 TP
2. 因为匹配与类别无关，这个 TP 被**记在真值类 A 名下**
3. 但该框的预测类别是 B → B 类的"预测数"涨了，B 类的 TP 没涨
4. 于是 **B 类 `fp = pred − tp` 可能变成负数**，进而 `precision = tp/(tp+fp) > 1`

代码原作者（本项目）在模块 docstring 里已明确标注这一点，并说明历史基线里 `striated_scale` 出现过 `fp=-2 / P=1.105` 就是这个原因。

---

## 三、两种口径的定义与差异

| | 默认（`strict_tp=False`） | `--strict`（`strict_tp=True`） |
|---|---|---|
| 匹配方式 | 类别无关，只看 IoU | 同类才算匹配 |
| TP 归属 | 真值类 | 预测类 == 真值类才记 TP |
| fp / fn | **可能为负** | 恒 ≥ 0 |
| precision | **可能 > 1** | 恒 ≤ 1 |
| 语义 | "定位到了缺陷就算对，类别不管" | "定位 + 分类都对才算对" |
| 与历史基线 | **可比** | 不可比（更严格） |

**默认口径衡量的是"缺陷发现能力"，strict 口径衡量的是"缺陷识别能力"。** 工业质检要的是后者——把折痕报成划痕，下游处置动作会不一样。

---

## 四、同一模型的两种口径实测（100 轮 strat，3020 张新 holdout）

| 阈值策略 | 口径 | TP | FP | FN | P | R | F1 |
|---|---|---|---|---|---|---|---|
| uniform 0.20 | 默认 | 3865 | 1239 | 1828 | 0.7572 | 0.6789 | **0.7159** |
| uniform 0.20 | **strict** | 3733 | 1371 | 1960 | 0.7314 | 0.6557 | **0.6915** |
| per-class 标定 | 默认 | 3786 | 1133 | 1907 | 0.7697 | 0.6650 | 0.7135 |
| per-class 标定 | **strict** | 3679 | 1303 | 2014 | 0.7385 | 0.6462 | **0.6893** |

**strict 下负 fp / P > 1 的类：无**（39 类全部干净）。

### 关键差值 = 跨类混淆的代价

```
3865 − 3733 = 132 个框
```

这 132 个框是**定位正确、类别判错**的。换算成 F1：`0.7159 − 0.6915 = 2.44pp`。

也就是说：

- 模型的**缺陷发现能力** ≈ 0.7159
- 模型的**缺陷识别能力** ≈ 0.6915
- **跨类混淆吃掉 2.44pp**

这个数字本身就是有价值的分析结论，比单一 F1 更能说明问题在哪。

## 五、对文档的影响与建议

### 5.1 已发布的数字需要标注口径

| 位置 | 当前写法 | 建议 |
|---|---|---|
| `docs/board_eval_20261020.md` | 板端 F1 0.7376 / 0.7506 | 加注"默认口径（TP 记真值类）" |
| PPT v3 P13 | holdout F1 0.7159 | 加注口径，或补一行 strict 0.6915 |
| PPT v4 P10/P11 | 0.7159 / 39 类 F1 柱图 | 同上 |
| 讲稿 v3 P13 | 念"Holdout F1 = 0.7159" | 口播时补一句口径说明 |

### 5.2 论文建议（重要）

**正式结果用 strict 口径**，理由：

1. 内部自洽（fp/fn ≥ 0、P ≤ 1），经得起审稿人检查
2. 符合工业语义（类别错 = 处置错）
3. 可以顺带把"默认 vs strict 差 2.44pp"写成一段**跨类混淆分析**，是加分项

同时保留默认口径数字作为"与历史基线可比"的对照，两者并列呈现，并说明差异来源。

### 5.3 板端对比不受影响

板端 `_board_ab_eval.py` 的口径是**贪心匹配 + TP 记真值类**（同样是类别无关），与默认口径一致。因此：

- 板端 e50 vs strat 的对比（0.7376 vs 0.7506）在**同一口径下**进行，结论方向不受影响
- 但绝对值的语义要注明是"缺陷发现能力"
