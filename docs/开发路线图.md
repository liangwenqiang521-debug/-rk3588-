## 0. 背景与目标

在产线现场对工件表面与织物进行**实时视觉缺陷检测**，要求：
- 实时性：单图推理 + 上报满足产线节拍
- 准确性：可量化的检出率 / 误检率
- 可运维：上位机可视化、报警、统计、历史追溯、与 PLC 联动
- 可发表：形成可投稿至 IEEE TII / T-ASE / JIM / Measurement / TPAMI / CVIU 的完整工作

调研结论：采用 **RK3588（NPU 6 TOPS int8，RKNN 生态）** 作为边缘推理核心；上位机沿用当前 PyQt5 6 页面框架，逐步接入真实链路替代模拟检测。

## 2. 模型部署流水线（来自 PPT P2，RK3588 路径）

```
PyTorch 神经网络训练
       │  服务器训练并保存 .pth 权重
       ▼
导出 ONNX 模型（onnx 文件）
       ▼
┌──────────── 模型优化与转换 ─────────────┐
│  模型量化 (INT8/FP16) → 算子融合 → 校准数据验证 │
└──────────────────────────────────────────┘
       │  转换工具（RKNN-Toolkit2）
       ▼
生成 RKNN 模型（.rknn 文件）
       ▼
┌──────────── 应用部署（边缘端） ──────────┐
│  加载 RKNN（Python/C++ API）→ NPU 加速推理 → 后处理与业务逻辑 │
└──────────────────────────────────────────┘
```

## 5. 阶段 P1 · 数据准备

**目标**：形成可用于训练与量化的**校准 / 训练 / 验证**数据集。

### 5.1 数据源

| 数据集 | 用途 | 规模 | 备注 |
|---|---|---|---|
| **NEU surface defect database** | 工业表面（铝型材）缺陷检测 | 6 类 × 300 张 | http://faculty.neu.edu.cn/songkechen/zh_CN/zdylm/263270/list/index.htm |
| **ZJU_LEAPER / The Fabrics Dataset** | 织物异常检测 | 视数据而定 | 织物场景备选 |

### 5.2 数据工程

- 数据清洗：去重、去模糊、剔除无标注
- 标注规范：YOLO 格式（class, x, y, w, h，归一化），与 RKNN 流程兼容
- 数据划分：train / val / **calib**（INT8 量化校准集，独立于 val）
- 增强：mosaic、mixup、HSV 抖动、随机翻转（与 ultralytics 一致）
- 数据闭环：上位机历史记录导出 → 反哺训练集（**自学习闭环**）

**交付物**：
- `datasets/neu/{images,labels}/` + `data.yaml`
- `datasets/fabric/...`
- 数据集说明文档（类别、分布、增强策略）

## 6. 阶段 P2 · 模型训练与转换

**目标**：在 PC 服务器训练 PyTorch 模型，端到端生成可在 RK3588 跑的 `.rknn`。

### 6.1 训练（PC 端 / GPU 服务器）

- 框架：**PyTorch + ultralytics**（YOLOv8 / YOLOv11 视效果选型）
- 任务类型：
  - 工业表面 → 目标检测（6 类 NEU 缺陷）
  - 织物 → 异常检测（PatchCore / EfficientAD / YOLOv8-seg 视结果）
- 训练产物：`.pt` 权重 + `runs/` 训练曲线
- 评估指标：mAP50 / mAP50-95、Recall、Precision、单图推理时延

### 6.2 导出与转换（PC 端 → RK3588 端）

| 步骤 | 工具 | 产物 |
|---|---|---|
| 导出 ONNX | `torch.onnx.export` / `YOLO.export(format='onnx')` | `.onnx` |
| 模型量化 | RKNN-Toolkit2 `load_onnx` + `quantization` | `.rknn` (INT8/FP16) |
| 算子融合 | RKNN-Toolkit2 内部 | — |
| 校准验证 | 校准集量化误差评估 | accuracy report |
| 精度对齐 | 同一测试集对比 PC / RK3588 推理结果 | 对齐报告 |

**关键验证**：
- PC 端 mAP 与 RK3588 端 mAP 差异 ≤ 1%
- 单图推理时延 ≤ 30ms（RK3588 NPU @ int8）

**交付物**：
- 训练脚本（可复用）
- 量化转换脚本（ONNX → RKNN）
- 精度对齐报告
- `models/*.rknn`（按数据集 / 任务分类管理）

## 7. 阶段 P3 · 边缘端部署

**目标**：RK3588 上稳定运行：取流 → 推理 → 输出 → I/O 触发。

### 7.1 相机接入

- 海康威视 GigE 相机 + MVS SDK for ARM/Linux
- 触发模式：硬件触发（PLC 给相机触发信号）/ 软触发 / 连续采集
- 曝光、增益、白平衡按工件特性调参
- 掉线重连、心跳上报

### 7.2 推理服务

- 加载一个或多个 `.rknn`（按任务/型号）
- 图像预处理：resize / 颜色空间 / 归一化（与训练一致）
- NPU 推理（`rknn.runtime`）
- 后处理：NMS、阈值过滤、坐标反归一化
- 输出结构：`{timestamp, image_id, defects:[{class, score, bbox}], total_ms}`

### 7.3 I/O 与 PLC 联动

- STM32 控制板（复用 Nano GPIO）做：
  - 报警灯 / 蜂鸣器（NG 触发）
  - 传送带启停 / 推杆信号
  - 与上位机通信（UART / Modbus）

### 7.4 边缘端软件形态

- 进程模型：相机采集 + 推理 + 通信 三线程
- 通信接口（向上位机）：
  - TCP（JSON 报文）或
  - gRPC（推荐，便于跨平台） / 
  - 串口（兜底）
- 健康上报：CPU/NPU/温度/帧率/丢帧

**交付物**：
- 边缘端推理服务（Python 或 C++，视性能定）
- MVS 取流 + RKNN 推理 demo
- 通信协议文档

## 8. 阶段 P4 · 上位机集成

**目标**：把当前 PyQt5 上位机从"模拟检测"切到"接收真实边缘结果"。

### 8.1 现有上位机资产（可复用）

- 6 个功能页面：实时检测、参数设置、历史记录、通信设置、运行日志、NPU 监控
- 已具备：实时取流接口、NG 报警（声音 + 闪烁）、良率趋势图、历史记录（SQLite）、参数配置（config.json）、psutil 系统监控、串口/NPU 监控
- 通信设置页已可连接 PLC 串口

### 8.2 需要改造/新增

| 页面 | 改造点 |
|---|---|
| **实时检测** | 替换模拟帧来源 → 边缘端 TCP/gRPC；检测结果渲染改为真实 bbox + 类别 + 置信度；保留 NG 报警 |
| **通信设置** | 新增"边缘设备"连接（IP/端口/协议），与现有串口并列；支持重连与状态展示 |
| **参数设置** | 模型路径（.rknn）、推理阈值、报警阈值与边缘端配置对齐 |
| **历史记录** | 字段对齐：缺陷类型 / 坐标 / 置信度 / 推理时延 / 原始图 |
| **NPU 监控** | 从"本地 RK3588 debugfs"扩展为"远端 NPU 指标上报"（若上位机与边缘分离） |
| **运行日志** | 接入边缘端日志（syslog / TCP 转发） |

### 8.3 接口约定（上位机 ↔ 边缘端）

- 控制命令：开始/停止/切换模型/参数下发
- 推送：检测结果（JSON）、状态/健康（周期）、报警事件
- 心跳 + 断线重连

**交付物**：与边缘端协议对齐的代码改造 + 联调记录。

## 13. 风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| RKNN 量化掉精度 | 检出率下降 | 校准集选型 / 混合精度 / 逐层对比 |
| MVS SDK ARM 兼容性 | 取流失败 | 提前在开发板验证 / 备选 V4L2 |
| 产线节拍 vs 推理时延 | 漏检 | 流水线 + 多线程 + 模型剪枝蒸馏 |
| 数据集获取受限 | 训练停滞 | 优先 NEU（公开），织物用自采兜底 |
| 上位机改造范围失控 | 项目延期 | 阶段 P4 严格按接口解耦，分步切换 |
| 论文与系统耦合过深 | 写作难 | 创新点提前在 P2–P3 沉淀实验素材 |
