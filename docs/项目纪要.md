# 项目纪要：硬约定与工程经验

> 本文件是公开版的工程约定汇总，替代早期含内网信息的内部工作日志。
> 原始逐日开发日志不随仓库分发。

## 一、硬约定（改动前请先确认）

| 项 | 约定 | 原因 |
|----|------|------|
| 串口波特率 | 全链路 **1500000** | 板端固件与上位机必须一致，仅少量诊断脚本保留 115200 |
| 界面图标 | **一律纯文字**，不用 emoji | 部分平台字体缺字形，emoji 会渲染成方块 |
| 截图验证 | 必须真实平台，禁用 `QT_QPA_PLATFORM=offscreen` | offscreen 下中文字体不渲染，截图不可信 |
| `main.py::_install_crash_guard()` | **不可删除** | PyQt5 槽内未捕获异常会导致进程静默死亡（无 traceback、exit 127） |
| `tcp_bridge.py` 背压 `MAX_INFLIGHT` + `ack()` | **不可去除** | 去掉后每帧 JSON 含 base64 图，GUI 跟不上时内存线性上涨（实测 +27MB/min） |
| 边缘语义 | 连板后「开始检测」只置 `_edge_detect_enabled`，不启本地推理 | 板端负责推理，上位机只做展示与统计 |
| 停止/清除/换图 | 三者都必须清场：`canvas.clear_result()` + `clear_defects()` + 右侧面板复位 | 否则残留上一件的结果误导判断 |
| `infer.py` 前 6 类顺序与配色 | **不可改动** | 与 RKNN 模型导出时的 `names` 索引一一对应 |

## 二、板端连接（`board_env.py`）

所有板端参数统一走 `board_env`，读取优先级：
**环境变量 > `board_env.local.py` > 占位默认值**。

```bash
# Windows
set BOARD_IP=192.168.1.20
set BOARD_PASS=yourpassword

# Linux / macOS
export BOARD_IP=192.168.1.20
```

或复制模板填写：

```bash
cp board_env.example.py board_env.local.py
```

`board_env.local.py` 已在 `.gitignore` 中，**不会**被提交。

## 三、血泪坑（避免重蹈覆辙）

### 3.1 OpenCV 与中文路径

⚠️ **`cv2.imwrite` / `cv2.imread` 在 Windows 下遇到含中文的绝对路径会静默失败** ——
`imwrite` 返回 `False`、`imread` 返回 `None`，**都不抛异常**。

曾因此导致 4320 张增强图「假生成」，训练集实际为空。

兜底写法：

```python
cv2.imencode(ext, img)[1].tofile(path)          # 写
img = cv2.imdecode(np.fromfile(path, np.uint8), cv2.IMREAD_COLOR)   # 读
```

训练前务必先跑 `模型训练/_dataset_check.py` 做体检。

### 3.2 RKNN 归一化必须成对

`rknn.config(mean/std)` 与 host 侧预处理是**叠加**关系，写错会出现
「分类头压塌但 box 正常」的症状（官方 `accuracy_analysis` 抓不到，
须用 onnxruntime 建外部基线对照）。

本项目约定：`.rknn std=255` ↔ host 送 **uint8 [0,255] NHWC**。

### 3.3 YOLOv11 导出 ONNX 的输出已是概率

后处理**不要再套 sigmoid**，否则置信度全错。opset 12 与 RKNN 2.3.2 兼容。

### 3.4 板端服务的「发送超时即判死」陷阱

推送线程若用 `settimeout(0.3)` + `sendall`，一旦上位机读得稍慢，超时会把
客户端当死连接 `close()`；而**上位机的 `sendall` 仍返回成功**，现象是
「推一两帧后再也不动」，极难排查。

正确做法：超时放宽到 5s，只有 `BrokenPipeError / ConnectionResetError / OSError`
才判死；`TimeoutError` 只丢弃本轮、保留连接。

> 注意：`TimeoutError` 是 `OSError` 的子类，`except` 顺序必须先写它。

### 3.5 自定义开关赋值不触发 Qt 信号

`switch.on = True` 只改属性，不会调用 `_on_xxx_toggled()`。
凡是「开关回调里才创建/启动的定时器」，直接改标志位时必须**显式再调一次启停**。

### 3.6 推理主循环必须包 try/except

`while True` 中任何一次未捕获异常都会静默退出线程 —— 表现为停止推帧，
但客户端还连着、端口还 LISTEN，从外部完全看不出问题。

### 3.7 「内存图」≠「文件图」

`set_image_bytes()` 会清空 `_image_path`，但 `has_image()` 仍为 `True`。
凡是要读文件的路径，必须判 `if path and os.path.exists(path)`。

### 3.8 Windows 控制台编码

控制台是 GBK，`print` 含 emoji 会 `UnicodeEncodeError`（如 U+2705）。
日志与终端输出一律用纯文字。

### 3.9 给板子写 shell 脚本

必须保证 **LF 换行**（CRLF 会导致 `bad interpreter`）。
用 Python `open(..., newline='\n')` 写入，不要依赖 heredoc。

## 四、防膨胀机制

| 位置 | 机制 |
|------|------|
| `db.py` | `MAX_ROWS=5000`，insert 前先判 count 再 trim 到 4000 |
| `utils.disk_guard()` | 磁盘 <10% 时按 mtime 删最老存图，保护 `存证_*` / `录制_*` |
| 边缘重 IO 门控 | 存图仅 NG 且间隔 ≥2s；入库 NG ≥0.5s / OK ≥1.0s |
| `tcp_bridge.py` | 背压 `MAX_INFLIGHT=2` + `ack()` |

## 五、长期常驻机制

| 脚本 | 周期 | 作用 |

| `模型训练/_weekly_feedback.py` | 7 d | 难例回流周报 |
